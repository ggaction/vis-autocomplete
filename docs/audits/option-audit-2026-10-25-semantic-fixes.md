# Semantic audit fixes

Implemented against the 2026-10-25 option audit. This note describes verified fixes, not an exhaustive claim about every chart/parameter combination.

## Changes

- **S01:** Radar series identity and color are independent. Small categorical groups default to one explicitly labelled mean profile per group. High-cardinality observation IDs are not default colors. Color choices that vary within a selected series are disabled with a reason. Individual observations require unique series identity.
- **S03/S04:** Follow-up Radar editing preserves the original source schema and nominal hints, including numeric class/ID fields. The dimensions control displays the actual axis order, supports reordering, and preserves that order when membership changes.
  Series choices check original-source membership before collecting incompatibility explanations, so folded dimension roles cannot reappear as disabled user choices.
- **Grouped profiles and normalization:** Public `createRadarPlot` and `editRadarPlot` support `wide.summary: false | "mean" | "median"` and `wide.normalize: false | "minmax"`. Native defaults do not aggregate or normalize; the app explicitly labels its grouped-mean default. Explicit minmax normalizes each dimension across the resulting profiles; constant dimensions map to zero. Unnormalized profile values remain in the folded data, and original observations remain in the source dataset. Native public summary/fold/normalize actions own the derived pipeline, with obsolete revisions released.
- **Income/rate controls:** Line, Bar and Area expose a weighted mean when a selected, valid nonnegative weight is available. It calls public `createSummaryData` with reliability weights. Weighting requires choosing Weighted mean; the visible Weight control proposes a suitable column and remains editable. Weight eligibility also checks positive total weight in every displayed group using that same native summary/bin plan, and refreshes when bin membership changes. Zero-weight observations remain valid when their group's total is positive. Rate-like fields whose actual values are in [0,1] default to unweighted mean and percentage labels. The user can switch number/percent formats.
- **Numeric bins:** Native Bar/Line bin axes use inferred boundary ticks and an explicit `(binned)` title. Area/Horizon computed summaries disclose `(bin centers)` in the title. No static center-to-interval label map is stored: changing bins must not leave old intervals or out-of-domain tick values behind. The underlying observed rows and bin arithmetic remain native.
- **A02:** Clearing Parallel Coordinates color no longer recreates a fieldless color encoding while adding the palette.
- **C05:** ECDF's mapping Color control drives both the actual group and categorical color encoding; stale Group=None values cannot override the selected mapping. Color=None remains a valid uncolored distribution.
- **A10:** A color-only line/Radar legend can coexist with a new dash encoding of a different field. The old color legend moves to a distinct native owner while preserving appearance; matching fields extend a combined series legend. Direct repeated creation of an already-created channel remains an error.
- **Legend regression checks:** The migration occurs only when another legend owner is needed; merely encoding dash does not change a color-only legend's resource identity. Local corner placement uses the existing 8px corner gap when the former outside offset was inferred, while explicitly authored offsets remain intact. Independent primitive/pixel oracles were retained unchanged.
- **Architecture:** Facet automatic legend preparation uses its already-filtered explicit owner/channel requests and invokes the public legend creator. Removing a redundant import of the action planner restores an acyclic materialization→grammar/selector dependency without weakening architecture checks. Suppressed color remains absent when a new shape or stroke legend is inferred and after persistence replay.
