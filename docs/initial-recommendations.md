# 데이터가 비슷하면 어떤 차트를 썼는가

초기 차트 추천은 유사한 데이터셋의 실제 차트 사용 비율을 검색해 합친다. 차트를 고른 뒤에는 기존 논문의 공동출현 엔진으로 다음 액션을 추천한다. 두 점수는 서로 섞지 않는다.

## 1. 전체 코퍼스에서 예제를 만든다

`npm run corpus:update`는 모든 차트 디렉터리를 발견하고 데이터, G1–G8 번역 코드, 원본/해결된 Vega-Lite 명세를 읽는다. metadata의 SHA-256과 대조하며 코퍼스의 JavaScript를 실행하지 않는다.

한 차트 ID는 한 표다. 번역 단계 수만큼 빈도를 늘리지 않는다. 원본 명세에서 차트 의미를 읽기 때문에 저수준 `createBarPlot`로 실현된 Histogram을 Bar로 잘못 세지 않는다. 명세가 없으면 실제 공개 plot 호출, 마지막으로 primitive mark와 encoding을 사용한다. Text/Rule 주석은 다른 주된 차트가 있을 때 별도 plot으로 세지 않는다. 여러 차트 종류가 합성되면 고유 종류 수로 한 표를 나눈다. 해석하지 못한 종류는 감사 보고서에 남긴다.

## 2. 데이터 중복과 원본 계열을 묶는다

키와 행 순서를 정렬한 타입 보존 지문으로 동일한 표를 묶는다. 중복 행의 개수, 열 사이의 값 대응, 숫자와 숫자 문자열의 차이는 유지한다. 생략된 값과 null, ISO 날짜의 자정 표기 차이는 중복 판별에서만 동일하게 취급한다. 입력 데이터 자체는 수정하지 않는다.

동일한 원본 HTTP 데이터 URL을 공유하는 변형은 원본 계열로 연결한다. 검색에서는 한 계열에서 현재 입력과 가장 가까운 데이터셋 하나만 채택한다. 따라서 같은 원본의 복사본이 여러 이웃 자리를 차지하지 않는다. URL이 없거나 알려지지 않은 변형까지 완전히 찾아내는 방식은 아니다.

데이터셋 d의 차트 종류 t 비율은 다음과 같다.

```text
p_d(t) = 데이터셋 d의 차트 중 t가 받은 표의 합 / 데이터셋 d의 전체 표의 합
```

이 비율을 이웃의 한 표로 사용한다. 한 데이터셋에 차트 100개가 있고 다른 데이터셋에 1개가 있어도 전자가 100배 큰 이웃 가중치를 갖지 않는다. 현재 스냅샷은 1,213개 차트, 843개 고유 데이터셋, 842개 원본 계열이다.

## 3. 현재 입력도 같은 통계로 표현한다

`src/dataset-profile.js`를 학습과 브라우저 양쪽에서 사용한다. 필드 이름과 차트 레이블은 거리 계산에 사용하지 않는다.

| 통계 블록 | 예 |
|---|---|
| 크기 | log 행 수, log 열 수 |
| 타입 | 수치·범주·시간·숫자 문자열·혼합 비율 |
| 결측 | 평균·최대 결측률 |
| 고유값 | 고유값 수, 유일성 비율, 범주 cardinality |
| 분포 | 엔트로피, 상수 열, robust skew/tail, 0·비음수 비율 |
| 관계 | 절대 Pearson 상관의 평균·최대, 높은 상관 비율, 조합 coverage |
| 시간 | 시간값의 유일성과 반복 |

총 31개 특징이다. 단일 열 통계는 전체 행과 전체 열을 읽는다. 관계 통계는 값 기반으로 결정적으로 뽑은 최대 512행·32개 수치 열을 사용하되, 경계 동률은 함께 포함한다. 따라서 동률 때문에 실제 개수가 한도를 넘을 수 있다. 행·열 순서나 이름을 바꾸어도 같은 벡터를 만든다. 비어 있는 데이터와 극단적으로 큰 수치도 유한한 값으로 처리한다.

각 특징을 학습 데이터의 5–95 백분위수 범위로 [0, 1] 정규화한다. 범위가 같으면 min/max를 사용한다. 블록별 평균 절대 차이를 구하고 7개 블록을 동일한 가중치로 평균한다.

```text
d(q, d) = (1 / 7) Σ_block mean_feature |normalized(q) - normalized(d)|
```

특징이 많은 블록이 자동으로 더 큰 비중을 차지하지 않는다.

## 4. 이웃의 차트 비율로 점수를 만든다

최대 k=40개 원본 계열을 가까운 순서로 검색한다. 현재 선택된 inverse-square 커널은 다음과 같다.

```text
w_d = (가장 가까운 거리 / d(q, d))²
score(t | q) = Σ_d w_d × p_d(t) / Σ_d w_d
```

거리 0인 이웃이 있으면 그 일치 이웃만 동일 가중치로 사용한다. 표본이 통계적으로 같다는 뜻이며 데이터 값이나 의미까지 같다는 보장은 아니다. 그 경우 유효한 이웃 수는 40보다 적을 수 있다.

k와 커널은 개발 데이터의 교차검증에서 선택한다. 후보는 k=10/20/40과 inverse-square/exponential이다. 개발 top-1 점수를 우선하고 MRR로 동률을 해소한다. 결과는 `data/initial-evaluation.json`에 남는다.

학습 증거가 없는 plot에는 빈도나 수동 가산점을 만들지 않는다. 현재 코퍼스에 관측된 지원 plot은 12종이며 갤러리의 29종 전체를 학습했다고 주장하지 않는다. 나머지도 점수 0으로 탐색할 수 있다. ggaction에서 실행할 수 없는 종류는 이유와 함께 뒤에 둔다.

점수는 유사 데이터셋의 관측 비율이며 사용자 만족 확률이나 차트 품질 점수가 아니다. 현재 입력과 같은 데이터가 코퍼스에 있으면 그 사용 사례도 검색된다. 새 데이터에 대한 일반화 성능은 별도 분리 평가로 확인한다.

## 5. 변수 기본값도 이웃에서 가져온다

추천된 plot과 같은 종류의 예제에서 X/Y/색상 등이 어떤 타입·결측률·고유값·분포를 가진 열을 사용했는지 읽는다. 현재 데이터의 선택 가능한 열과 통계 거리를 비교해 기본값을 정한다. 원본 명세의 인코딩 타입도 반영한다. 위치 변수는 중복 선택을 피한다.

이 과정은 파라미터 기본값만 바꾸며 plot 점수에는 영향을 주지 않는다. 선택 가능한 열은 그대로 유지하고, 실제 native ggaction 실행에서 인자가 거절되면 기존의 호환 기본값으로 되돌린다. 이웃 근거와 fallback 여부는 예제 JSON에 기록한다. 모든 매핑과 비수치 파라미터까지 학습한 모델은 아니다.

추천은 `program.createScatterPlot({...})` 같은 공개 함수 호출 하나다. `createGuides`는 기존 앱의 가이드 정책에 따라 항상 마지막에 한 번 붙는다. 프리뷰와 Apply가 같은 함수와 인자를 실행한다.

## 6. API와 화면

```js
import { chart } from 'ggaction';
import { createInitialChartRecommender, profileDataset } from './src/index.js';

// model = JSON으로 읽은 data/initial-model.json
// rows = 수정하지 않은 원본 데이터
const program = chart().createCanvas({ width: 700, height: 430 })
  .createData({ id: 'dataset', values: rows });
const engine = createInitialChartRecommender(model);
const result = engine.recommend(rows, profileDataset(program, 'dataset'));
const first = result.recommendations[0];
console.log(first.method, first.build(first.values), first.score, first.evidence);
```

`recommend()`는 순위와 제안 인자를 반환한다. 실제 실행 검증과 fallback 선택은 앱의 `prepareGuidedAction` 또는 `examples/initial-demo.js`를 따른다. `call` 문자열을 eval하지 않는다.

화면은 초기 추천 29개를 다섯 개씩 가로 페이지로 보여준다. 보이는 페이지와 이웃 페이지만 실제 차트를 미리 렌더링한다. 카드 호버·파라미터 호버·고정·확정 전 코드·Apply만 확정하는 동작은 유지한다. Apply 후에는 기존 논문의 공동출현 점수로 다음 함수 다섯 개를 추천한다.

## 7. 평가와 검증의 범위

원본 계열을 결정적인 해시로 다섯 fold로 나누고, fold 0은 최종 테스트로 남긴다. 나머지 fold에서 k/커널을 교차검증한다. 정규화 범위도 각 학습 fold에서만 구한다. 테스트 데이터의 차트 레이블은 선택 과정에 사용하지 않는다. 한 계열의 알려진 변형이 학습과 테스트에 나뉘지 않는다.

각 테스트 데이터셋에 여러 관측 차트 종류가 있으면 그 비중으로 top-k 적중과 reciprocal rank를 계산하고 데이터셋 간 평균을 낸다. 현재 독립 테스트는 182개 데이터셋이다.

| 순서 | Top 1 | Top 3 | Top 5 | MRR |
|---|---:|---:|---:|---:|
| 유사 데이터 검색 | 66.97% | 92.32% | 95.89% | 0.7912 |
| 기존 고정 순서 | 23.02% | 88.38% | 90.86% | 0.5159 |
| 학습 데이터 전체 빈도순 | 31.07% | 88.38% | 94.78% | 0.5803 |

이 수치는 현재 코퍼스의 차트 선택을 얼마나 예측하는지 나타낸다. 품질에 대한 사용자 평가나 통계적 유의성 검증은 아니다. 소수 종류, 특수 차트, 알려지지 않은 중복 원본, 코퍼스 편향은 한계로 남는다.

`npm test`는 차트 중복 제거, 데이터셋 편향 방지, 원본 계열 분리, 데이터 불변성, 순위 변화, 실제 한 함수 실행, 새 차트 추가와 잘못된 SHA에서 이전 모델 보존을 확인한다.

`npm run validate:initial`은 모든 1,213개 데이터 파일을 읽고 각 표의 첫 128행으로 가장 높은 호환 plot과 마지막 가이드를 실행한다. 현재 1,142개는 실행 성공, 71개는 현재 plot의 조건을 만족하지 않아 별도 기록, 예상 밖 실패는 0개다. 원본 8,788개 번역 프로그램 전체의 재현이나 픽셀 동등성 검사는 아니다.

## 8. 새 차트 추가와 재현

```sh
npm run corpus:update   # 최신 코퍼스 수집 + 두 모델 재계산 + 초기 평가
npm test
npm run demo:initial
npm run validate:initial
# 라이브러리 upstream과 함께 갱신하고 전체 검증하려면 npm run update
```

ID 목록과 차트 수를 코드에 추가하지 않는다. 모든 입력 해시는 매번 검사하고, 버전과 해시가 맞는 데이터 통계만 캐시에서 재사용한다. 파싱·해시·원본 파일 오류가 있으면 기존 배포 모델을 덮어쓰기 전에 실패한다.

- `src/dataset-profile.js`: 공유 통계 추출
- `src/chart-evidence.js`: 원본 명세와 정적 함수 호출에서 차트 의미 추출
- `scripts/initial-corpus.js`: 데이터셋 지문, 원본 계열, 차트 표, 평가
- `src/initial-recommender.js`: 거리 검색, 점수, 변수 역할 대응
- `data/initial-model.json`: 브라우저가 그대로 읽는 인덱스
- `data/initial-corpus-report.json`: 차트별 사용 여부와 감사 정보
- `data/initial-evaluation.json`: fold별 선택과 테스트 결과
- `output/initial-demo.json`: 두 입력의 호출 인자와 모든 이웃별 기여도
- `output/initial-validation.json`: 전체 데이터 실행 검증
